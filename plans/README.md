## Recommended execution order (rationale)

1. **001–005 first**: the five Tier-1 user-facing bugs — all high-confidence,
   each with its regression test in the same plan. 002 before 012; 005's belt
   constant is named so 018 stays mechanical.
2. **006–008**: the remaining small correctness fixes and the static
   contract checks. 008 lands BEFORE any plan that edits the inlined copies
   (009, 010, 012) — it is the guardrail that keeps those edits honest.
3. **009–013**: the larger code work (clamp loop, shadow roots, phantom
   recovery, perf), each gated by the checks/tests from the plans before it.
4. **014–015**: test-infrastructure hardening and the real-browser boost
   path — placed after the code fixes they will pin.
5. **016–020**: independent small items and the investigation plan; run any
   time, but 016 is cheap and high-value (do it early if preferred).

## Findings considered and rejected

(Recorded so nobody re-audits them; full reasoning in the audit report.)

- **SEC-01 as a security finding** ("page-reported rates are unvalidated"):
  rejected — reports originate only from `report(el.playbackRate)`
  (platform-clamped element values) and adopting page-chosen rates is the
  documented R5 product behavior the page could effect directly. Residue
  kept as hardening in plan 007 (clamp symmetry + the `fmtSpeed(0)`
  display quirk).
- **popup.js god-file refactor / module split**: rejected — 15 bannered
  sections, one render path, consistent optimistic-then-reconcile
  discipline; the concrete costs are filed as plan 019's duplication. A
  split is not warranted for a personal-use, framework-free repo.
- **ESLint / TypeScript / CI pipeline**: rejected — deliberate, documented
  zero-dependency simplicity; `npm test` + harness + e2e cover the
  dangerous failure classes (and `npm test` was re-verified passing during
  the audit).
- **Perf micro-items** (per-tick probe cost, per-render SVG rebuilds,
  session-storage write volume, offscreen graph efficiency, slider layout
  thrash): rejected — popup-lifetime or user-paced; below the finding bar.
- **`near()` tolerance unification** (1e-6 / 1e-3 / 1e-9 across files):
  rejected — each tolerance matches its data; no constructible failure.
- **Popup `muteAll` vs keyboard `mute-all` "duplication"**: rejected —
  different tab universes by documented design (the command must work with
  no popup).
- **`test/make-tone.mjs` as dead code**: rejected — it generates the
  committed `test/media/tone.wav` fixture.
- **REVIEW-STATUS.txt overlapping the README**: rejected — intentional
  release-archive status document.
- **Code-side privacy mitigations** (gating `noteFrameCommit` on
  `enforcementNeeded()`, restricting artwork to `data:` URLs): deliberately
  deferred, not rejected — documented as maintainer options in plan 016.
- **`persistCommitted` write-deduplication** (from PERF-2's finding):
  deferred — session storage is RAM-backed and commits are user-paced;
  noted in plan 012's maintenance section.

## Product direction (NOT planned — for separate maintainer decision)

Per the operator's instruction, the three grounded direction suggestions
from the audit are intentionally NOT turned into implementation plans:

1. **Per-hostname speed memory (opt-in)** — the override machinery makes it
   cheap; PLAN.md explicitly defers it as a future opt-in.
2. **A keyboard command for boost** (`Alt+Shift+B`) — commands grant
   `activeTab` just like the toolbar; boost is the only primary control
   without a shortcut.
3. **Playlist autoplay as a policy-gated opt-in** — revisits a PLAN.md
   deferral; only honest "while a speed policy is active" (the manager
   already lives in the page then); a design/spike task if wanted.
