media-control-panel — release status

What this archive is
  The unpacked extension at the archive root (manifest.json), together with its
  test fixtures, scripts, documentation and screenshots.

Loading
  Chrome: chrome://extensions -> Developer mode -> Load unpacked -> select the
  extracted folder (in the repository this is the extension/ folder).
  Edge: same flow; Edge is supported as an optional secondary browser.

  npm run harness       real background.js + popup.js against an in-memory
                        chrome.* mock; no installed extension, no network.
  npm run e2e           unpacked extension in real Chrome; popup driven as an
                        extension page; full feature and regression matrix.
  npm run youtube-check real youtube.com in a headed Chrome window: mute
                        matrix and actual playback at 2x-16x.
  npm run shots         regenerates the screenshots from the REAL action popup
                        (chrome.action.openPopup) via CDP.

Known limitations
  - YouTube synchronization uses the first-party player's INTERNAL
    #movie_player methods (the same names the IFrame API uses). They are NOT
    the official YouTube IFrame Player API, are undocumented, and may change;
    the adapter feature-detects them and falls back to the media element,
    which always works but may not move YouTube's own UI.
  - Spotify and SoundCloud expose no reliable public player API: their native
    UI is not synchronized (element-level readout stays truthful).
  - The action popup's outer frame, shadow and window decorations are owned by
    the browser (square on Chrome). CSS styles only the popup content; the
    document paints the theme colour edge to edge. Screenshots show the popup
    content, not the browser-owned frame.
  - Media inside closed shadow roots, DRM-protected pages and WebAudio-only
    playback is unreachable for this kind of extension.
  - MediaStream (srcObject) elements are skipped by the speed manager
    (Chromium clamps their playbackRate).
